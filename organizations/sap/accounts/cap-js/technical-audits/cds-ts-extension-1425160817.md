## Project purpose

A TypeScript Language Service Plugin that provides CQL-aware completions, hover, diagnostics, and type inference inside cds.ql... tagged template literals in .js/.ts files.

## Why this project is used

Plugin for the TypeScript LSP to provide CDS-relevant capabilities, such as code completion within CQL queries, and type propagation of such queries.

## Limitations and caveats

- Known Limitations: - this extension currently does not work in a monorepo-scenario or when multiple workspaces are opened in a single vsode instance.
- Known Limitations: - draft-only associations (e.g. DraftAdministrativeData) are not resolved in queries against .drafts entities, so a reference like cds.qlSELECT DraftAdministrativeData.InProcessByUser FROM MyEntity.drafts is flagged Unknown source. These associations are generated by CAP only at runtime and do not exist in the compiled CSN the extension reads.
- Known Limitations: - The cds build plugin (cds-plugin.js) requires typescript to parse source files. In pure-JavaScript CAP projects that do not have TypeScript installed, the build-time CQL validation step is silently skipped with an info-level log message. Install typescript as a dev dependency to enable it.
