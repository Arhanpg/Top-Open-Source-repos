# Repository technical-audit progress

This file is regenerated by the scheduled technical-audit runner after each successful batch. It reports the number of YAML dossiers by status and the matching expected Markdown count.

## Current baseline

The inventory documentation currently reconciles 33,522 public repository records across 65 configured, inventory-eligible GitHub accounts. That is an inventory baseline, not a claim that those repositories have been technically audited.

Three manually interpreted sample dossiers are being added in this rollout to establish the intended level and structure:

- Apple: MLX.
- SAP: CAP Audit Logging.
- Amazon/AWS: Audit Plugin for MySQL.

The scheduled runner generates the remaining records in resumable round-robin batches. The first workflow run will replace this baseline with live generated counts.

## Interpreting counts

- `manual_reviewed`: a curated dossier manually checked against upstream documentation and selected build configuration.
- `llm_interpreted`: structured interpretation generated by the configured model from repository evidence.
- `evidence_only`: deterministic extracts captured; semantic interpretation is pending.
- `llm_error`: model interpretation did not complete; evidence-only output is preserved.
- `insufficient_evidence`: no usable README or meaningful description was found.

Counts refer to generated files and their status. They must not be presented as proof of exhaustive code audits, builds, tests, security reviews or complete discovery of all GitHub organizations for the 151 companies.
