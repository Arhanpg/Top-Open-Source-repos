## What each company page provides

Each company has a dedicated page showing its GitHub account mapping, verification status, and a repository inventory table. Each repository record is intended to document:

- Canonical GitHub repository URL and direct README URL
- What the project solves and its intended users
- Key features explicitly described in the README
- Languages, frameworks, dependencies, and infrastructure
- Default branch, license, archive state, and last update
- Evidence links and review date

## Evidence and accuracy rules

**An organization handle is not proof of company ownership.** Handles in the initial company index are research leads only. Company mappings must be checked against company-controlled websites, official engineering pages, or reciprocal links.

**A repository is not marked audited until its README has been inspected.** Do not infer technologies from the company sector, repository name, tags, or language metadata alone. Mark an entry as metadata-only when its README has not been reviewed.

GitHub search is ranked and paginated and is not an exhaustive organization inventory. For a complete public repository inventory, enumerate the verified organization’s repositories through all API pages; record the retrieval timestamp and whether pagination completed. Preserve archived repositories and label them rather than silently excluding them.

## Status legend

- `mapping unverified`: candidate GitHub account; official association not established.
- `metadata only`: repository metadata captured; README not reviewed.
- `README reviewed`: README opened and summarized with evidence.
- `README unavailable`: repository found, but README could not be retrieved.
- `no public org found`: no official public account verified after checking company sources.
